# PBR Vehicle Panel 使用指南

## 1. 环境与安装

本包需要 Python 3.9 或更高版本。进入交付包根目录后安装：

```bash
python -m pip install '.[gpu,pth]'
```

也可直接安装 `dist/` 中的 wheel。运行时不需要训练仓库、工作区源码或额外 `PYTHONPATH`。

太阳估计是可选集成。需要该功能时，再安装相邻交付的 `pbr-vehicle-sun 1.4.0` wheel；YOLO、SAM2、SSISv2 和 InfiniDepth 的环境及权重按该包的说明准备，并通过下文 JSON 配置传入。

车辆 Auto 识别也是可选集成。需要该按钮实际执行拟合时，可安装相邻交付的 `pbr-vehicle-auto 1.4.1` wheel；源码交付布局中也会自动发现相邻 `pbr-vehicle-auto/src/`，不要求 shell `PATH` 包含 console script。该版本默认把候选 PBR、mapping 和 CDF 计算放到本地 CUDA GPU；太阳光强度和亮度均固定在 Viser 滑条绝对区间 `[-0.3, 0.3]` 搜索，不以当前面板值为中心。

如果只加载 Gaussian PLY 场景，默认依赖即可。如果需要从 DriveStudio PTH 检查点中提取 Background Gaussian，请安装 PTH 可选依赖：

```bash
python -m pip install -e '.[pth]'
```

## 2. 资产目录

示例假设当前工作目录内有以下文件。路径可以按项目实际布局调整，也可以使用绝对路径；交付包中的示例统一使用相对路径以便迁移。

```text
.
├── scenes/
│   └── scene.ply                 # 或 checkpoint.pth
├── assets/
│   └── vehicle_example/
│       ├── pbr_vehicle_example.ply
│       └── configs/
│           ├── config_vehicle_example.json
│           └── config_scene_vehicle.json
└── .cache/
```

车辆主配置使用 `pbr-vehicle-single-ply-v1`，其中 `files.pbr` 指向车辆目录内的可见 PBR Gaussian；其 `normal_0..2` 用于着色，全局材质由 `material` 提供。

## 3. 打开面板

交付包不内置大体积场景或车辆资产。请按上一节结构准备调用方自己的 `scenes/` 与 `assets/`；以下命令中的路径均相对于当前工作目录，也可以替换为调用方机器上的绝对路径。

在交付包根目录执行：

```bash
python -m pbr_vehicle_standalone \
  --scene scenes/scene.ply \
  --vehicle-asset-folder assets/vehicle_example \
  --config assets/vehicle_example/configs/config_scene_vehicle.json \
  --port 18091 \
  --device auto \
  --scene-cache-dir .cache/pbr_vehicle_scenes \
  --vehicle-spacing 6.0 \
  --environment-map-resolution 128 \
  --seed 20260831
```

`--device auto` 是默认值：有 CUDA 时使用当前进程可见的 `cuda:0`，无 CUDA时回退 CPU。多卡机器可在命令外设置 `CUDA_VISIBLE_DEVICES=<卡号>`；程序内部仍使用逻辑 `cuda:0`，所以命令不依赖机器的物理编号或 GPU 型号。启动日志会打印实际设备名称。

启动成功后，浏览器访问 `http://localhost:18091/?fixedDpr=1`。`fixedDpr=1` 固定原生画布分辨率；省略时 Viser 可能为维持帧率自动降低分辨率。车辆面板中的暴露参数使用中文名称：太阳光强度、太阳方位角、太阳高度角、车辆色温、饱和度和亮度。色温范围为 `-0.5~0.5`（`0=6500K`），饱和度为直接倍率 `0~2`（`1` 保留原颜色），亮度为 `-1~1`（`0` 对应原 fill light `0.35`）。太阳光强度仍为 `-1~1`，两个角度保持度数。如果端口不是 `18091`，请使用 `--port` 指定的值。

在每辆车的 `高级 / Material` 中可切换“使用代理重光照”。默认开启时，Panel 在代理层计算 PBR 光照，并将光照比例映射到可见层，保持现有外观；关闭后不做比例回传，直接渲染 PBR Gaussian 的 Albedo、Normal、Roughness、Metallic 等朴素 PBR 结果。单 PLY 资产的两个逻辑角色共享同一套 Gaussian 数据；旧三文件资产关闭后会显示真实 `proxy_*.ply`。此开关随车辆配置保存，旧配置未包含该字段时按开启处理。

### 场景环境贴图

打开车辆的“高级 / R3GW Lighting”，勾选“使用场景环境贴图”。Panel 会在车辆中心捕获六个场景视图，捕获时自动隐藏所有插入车辆和投影，随后使用车辆法线、粗糙度、金属度、反射率以及当前相机方向计算漫反射和环境高光。车辆位置、旋转或缩放变化后会自动重新捕获；只移动观察相机时会复用已有 cubemap，只更新高光方向。

该功能默认关闭。关闭后立即恢复原有 SH 环境光预览；场景未加载、浏览器未连接或捕获失败时也会自动回退，不会阻断车辆显示。可在面板选择每个 cubemap 面的 `32/64/128/256` 分辨率，并用“刷新环境贴图”强制重建。启动时希望默认启用可加入：

```bash
python -m pbr_vehicle_standalone \
  --scene scenes/scene.ply \
  --vehicle-asset-folder assets/vehicle_example \
  --enable-environment-map \
  --environment-map-resolution 128
```

当前捕获结果是浏览器普通 Gaussian 渲染得到的 LDR cubemap，roughness 采用 mip 近似预过滤，适用于交互预览，不等同于物理 HDR 测量或离线 GGX importance sampling。

### 地面投影

`Projection` 中的 contact core 与 cast extension 仍由连续 RGBA mask 定义，但显示时会转换为有界 planar Gaussian 层，与场景 Gaussian 使用同一渲染通道。这样完整场景不会再覆盖跨通道透明平面。`Z offset (m)` 只调整物理接收面锚点，不用于修复渲染顺序；通常保持资产配置默认值即可。每层最多生成 50,000 个投影 Gaussian。

### Environment-map 环境球预览

在车辆的“高级 / R3GW Lighting / Environment-map 预览”中勾选“显示环境球”。六面 cubemap 会转换为经纬度纹理并贴到球面；捕获时自动隐藏所有插入车辆、contact/cast 投影和其他环境球。

- 关闭“跟随车辆”：用“独立采样 X/Y/Z”控制环境球的位置。每次改变位置都会在新位置重新捕获，球也显示在该位置。
- 开启“跟随车辆”：采样中心始终是车辆中心。用“显示偏移 X/Y/Z”设置球相对车辆中心的显示偏移；偏移只移动可视化球，不改变贴图的采样位置和内容。
- “显示环境球”和“使用场景环境贴图”是独立开关。只打开环境球不会改变车辆着色；只打开车辆环境贴图也不会显示球。
- 环境球设置随车辆 Config 保存和恢复。默认显示偏移为 `[0, -4, 2]` 米，球半径为 `1.5` 米。

### 太阳估计

将 [examples/sun-estimator-config.example.json](examples/sun-estimator-config.example.json) 复制到本机并按实际环境填写模型仓库、权重和数据集路径（这些路径只存在于调用方配置，不会写入交付包），然后在启动命令中加入。Panel 会自动发现已安装或相邻源码中的太阳估计入口，但不会猜测模型权重和外部环境路径：

```bash
python -m pbr_vehicle_standalone \
  --scene scenes/scene.ply \
  --vehicle-asset-folder assets/vehicle_example \
  --sun-estimator-config configs/sun-estimator.json \
  --sun-estimator-scene SCENE_ID \
  --sun-estimator-data-root datasets/processed/SCENE_ID \
  --sun-estimator-timeout 3600 \
  --port 18091
```

点击 Scene 区域的“太阳估计”后，Panel 会在后台调用 `pbr-vehicle-sun-scene`。按钮下方会持续显示进度条、“太阳估计状态”、“当前阶段”和“推理结果”；成功与失败都会进入明确终态。SSE-v9 生成的 `scene_result.json` 和诊断文件留在系统临时目录，成功发布的太阳方位角/高度角会自动填入共享光照控件；估计失败或未通过置信度门时，原有参数不会被覆盖。完整模型链仍由太阳估计包自身要求，Panel 不会加载或复制这些模型。

### Auto 识别车辆参数

将 [examples/auto-fit-config.example.json](examples/auto-fit-config.example.json) 复制为调用方配置。若 `pbr-vehicle-auto` 已安装，或源码交付中存在相邻 `pbr-vehicle-auto/src/`，可直接省略配置；Panel 会自动解析入口，不依赖 shell `PATH`。带配置启动示例：

```bash
python -m pbr_vehicle_standalone \
  --scene scenes/scene.ply \
  --vehicle-asset-folder assets/vehicle_example \
  --auto-fit-config configs/auto-fit.json \
  --auto-fit-timeout 600 \
  --port 18091
```

打开对应车辆，点击“Auto 识别车辆参数”。Panel 会在后台建立系统临时目录，把点击时的完整车辆状态作为模板交给 ALM-v5，并用完整场景 PLY 匹配。按钮下方会持续显示进度条、“Auto 识别状态”、“当前阶段”和“推理结果”；进度来自 fitter 的 `output/progress.json`，完成时显示回填值、指标变化和结果目录。若场景是 PTH，会先从 Background 转成完整缓存 PLY，不受显示层抽样影响。每次执行都在完全相同的绝对 UI 参数域中搜索：太阳光强度和亮度均为 `[-0.3, 0.3]`，不会因上一次结果回填而移动搜索窗口。搜索成功后，fitter 始终以 `candidate_only` 发布网格内最优候选，面板自动填写太阳光强度、亮度和车辆色温，同时将该车切换到独立光照并启用太阳。原始车辆 DC 只保留为指标基线，即使指标变化为零或负数也不再拒绝候选；命令失败、超时或输出无效时仍保持原值。太阳角度、太阳 RGB、饱和度、材质、变换和投影不会被覆盖。诊断、候选和烘焙 PLY 留在通知所示临时目录。

每辆车的 `Config` 面板提供保存、加载、重置和删除。`Reset vehicle` 会恢复该车辆首次加入时选中的配置状态，不会删除资产或配置文件。

已安装的包也可以使用等价入口：

```bash
pbr-vehicle-panel --scene scenes/scene.ply --vehicle-asset-folder assets/vehicle_example
```

`pbr-vehicle-viewer` 是为旧集成保留的兼容别名。

## 4. 命令行参数

| 参数 | 是否必填 | 默认值 | 功能 |
| --- | --- | --- | --- |
| `--scene PATH` | 否 | 不加载场景 | 初始场景路径。支持 Gaussian `.ply` 或 DriveStudio `.pth`。PTH 会先提取 Background Gaussian 并缓存为 PLY；只看车辆时可省略。 |
| `--vehicle-asset-folder PATH` | 否 | 不加载车辆 | 启动时加入的第一辆 PBR 车辆资产目录。程序会从其 `configs/` 目录解析主配置和 `pbr_*.ply`。 |
| `--config PATH` | 否 | 按随机种子选择 | 第一辆车的初始资产/面板 JSON 配置。通常与 `--vehicle-asset-folder` 一起使用。省略时会从资产目录的可用 `config_*.json` 中选择，没有其他配置时使用资产主配置。 |
| `--port PORT` | 否 | `18091` | Viser Web 面板监听端口。端口被占用时换用其他未占用端口。 |
| `--device DEVICE` | 否 | `auto` | PBR 计算设备。`auto` 优先本地 CUDA；也支持 `cpu`、`cuda`、`cuda:N`，并遵循 `CUDA_VISIBLE_DEVICES`。 |
| `--scene-cache-dir PATH` | 否 | `.cache/pbr_vehicle_scenes` | PTH 场景转换后的 PLY 缓存目录。加载原生 PLY 时不需要转换。 |
| `--scene-max-splats INTEGER` | 否 | `0` | 浏览器显示层的场景 Gaussian 上限；`0` 表示加载全部。仅在调用方主动接受显示抽样时设置正数。 |
| `--vehicle-spacing FLOAT` | 否 | `6.0` | 新增多辆车时的默认间距，单位与场景坐标系一致（通常为米），用于防止车辆初始位置重叠。 |
| `--seed INTEGER` | 否 | `20260831` | 未指定 `--config` 时选择初始配置的随机种子。相同资产集合和种子会得到可复现的选择。 |
| `--enable-environment-map` | 否 | 关闭 | 启动时为第一辆及后续新增车辆默认启用 scene-only cubemap IBL；运行时仍可逐车关闭。 |
| `--environment-map-resolution {32,64,128,256}` | 否 | `128` | 每个 cubemap 面的分辨率。较高分辨率能保留更细的反射，但捕获和传输成本更高。 |
| `--sun-estimator-config PATH` | 否 | 不启用 | 太阳估计 JSON。可写完整 `command`（支持 `{scene}`、`{data_root}`、`{output_dir}`、`{scene_path}` 占位符），或写 `pbr-vehicle-sun-scene` 的资源字段。 |
| `--sun-estimator-scene ID` | 否 | 当前场景文件名 | 传给太阳估计器的场景标识。 |
| `--sun-estimator-data-root PATH` | 否 | 空 | 太阳估计器使用的数据集场景根目录；若配置 JSON 含 `data_root`，则可省略。 |
| `--sun-estimator-timeout SECONDS` | 否 | `3600` | 单次太阳估计最长运行时间。超时后中间结果目录仍保留。 |
| `--auto-fit-config PATH` | 否 | 直接调用 `pbr-vehicle-auto-fit` | 车辆 Auto 识别 JSON。可指定 `executable`，或提供含 `{scene_ply}`、`{asset_dir}`、`{template_config}`、`{output_dir}`、`{final_config}` 占位符的完整 `command`。 |
| `--auto-fit-timeout SECONDS` | 否 | `600` | 单辆车 Auto 识别子进程的最长运行时间；超时不覆盖面板，中间结果仍保留。 |

所有参数都是可选的。不带参数启动时，可在面板中再输入场景或车辆资产路径：

```bash
python -m pbr_vehicle_standalone
```

## 5. GPU 选择

需要在多 GPU 机器上指定设备时，可使用标准 CUDA 环境变量：

```bash
CUDA_VISIBLE_DEVICES=0 \
python -m pbr_vehicle_standalone \
  --scene scenes/checkpoint.pth \
  --vehicle-asset-folder assets/vehicle_example
```

`CUDA_VISIBLE_DEVICES` 不是本程序的命令行参数。面板默认 `--device auto`；上例中的物理 GPU 会在程序内显示为逻辑 `cuda:0`。如需强制 CPU，添加 `--device cpu`。

## 6. 常用组合

只加载车辆：

```bash
python -m pbr_vehicle_standalone \
  --vehicle-asset-folder assets/vehicle_example
```

加载 PTH 场景和车辆：

```bash
python -m pbr_vehicle_standalone \
  --scene scenes/checkpoint.pth \
  --vehicle-asset-folder assets/vehicle_example \
  --scene-cache-dir .cache/pbr_vehicle_scenes
```

查看实时帮助：

```bash
python -m pbr_vehicle_standalone --help
```
